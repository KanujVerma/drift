# Prospective simulation v0.6

Issue [#693](https://github.com/KanujVerma/drift/issues/693). This is a
simulation. It is not a broker connection, a paper account, or evidence of
an investing edge. Twenty sessions are too short to support that claim.
Historical replay is a separate command and a separate directory; it does
not move this calendar. See [HISTORICAL.md](HISTORICAL.md).

The prospective pilot is not ready to launch. Live source and supervised
readiness checks do not establish prospective operation. This revision still
needs independent review, scheduler verification, runtime provenance and a
verified spending boundary. Earlier observation decisions without a matching review, intent,
and post-commit seal remain unverified and cannot execute through this workflow.
The workflow does not verify which model generated a proposal; model labels in
a file are caller assertions, not runtime attestations.

## Books

New windows use one ledger, `sol.sqlite`, starting with $10,000 simulated
cash and model identity `codex/gpt-6.2-sol@xhigh`. The process exports a
review for a supervisor; it does not invoke or authenticate the model. Runtime
identity and the spending boundary still need verification before launch.
Existing paired pilot windows retain their prior behavior. Original v0.2
observation books remain readable with their original mandate, instruments,
calendar and accounting. They are read-only: their original mandate lacks the
review, intent and execution-seal policy required for safe continuation.
Unsealed decisions cannot execute through this workflow or the manager API.
No records are converted or migrated. Continuous Terra/Sol comparison is deferred.

The collector and packet use the 13-symbol discovery research universe in
`drift.research.universe`. The pilot's separately declared simulated trading
mandate authorizes those same 13 names. A future research-universe addition
does not automatically extend that mandate. This is not a claim that these
names are the product universe.

## Local limits

Reused from the prior comparison where they still fit this book:

- position fraction 0.25 of the cost-basis denominator
- simulation fee $1 per fill, whole shares
- evidence age 336 hours, the multi-session path, not the 72-hour controlled cases
- for new books, partial-sale cost basis is allocated to the nearest cent,
  half-even; the remainder stays with the unsold shares. The allocated and
  retained amounts sum to the original basis. Existing books retain their
  original replay policy, so a legacy book with repeating-decimal basis can
  still refuse a later purchase. It is not silently migrated.

The prior cash floor was $20,000 of a $100,000 book. This book uses the same
20 percent, so the floor is $2,000. These are local test limits, not an
approved product mandate.

Fills use `post_decision_execution`. A decision is recorded before the fill.
The fill price comes from an eligible timestamped Alpaca trade after the
post-commit seal, plus the $1 fee. The collector requests the first eligible
print it can verify on the selected feed, excluding canceled and incorrect
prints. Identity includes the exchange and nanosecond timestamp. The age limit applies to observation
and availability times. A missing, stale, or pre-decision print is not
replaced with the cited close. One observation fills at most one decision per
book. A risk
rejection closes that decision and does not try a later price. A successful
fill moves the book clock, so a later submission cannot be dated before it.

Daily closes and the benchmark level are admitted only after that session's
exchange close. Their availability time is the fetch time, not the open.
The first post-close value is kept. A SPY price baseline is requested
after the first sealed decision while the book remains in cash. If that baseline
or a compatible closing price is missing, the comparison stays unavailable.
`--now` does not open or backdate an observation session. The five sessions
after the twentieth can ingest and fill, and do not accept new decisions.

`benchmark_relative` compares the book and SPY from the first post-decision
closing observation at which the book can be valued, through the reported
session's close. Earlier returns and dividends are excluded. The separate
`price_return_benchmark` retains its post-seal trade baseline and remains
unavailable when its stricter timing checks cannot be met. Legacy paired
windows retain their common-start comparison.

A hold with empty `evidence_ids` is an abstention. It does not invent a
citation. Buy and sell checks are unchanged.

## Sources

Collected by `python -m drift.prospective collect`:

- SEC submissions for filings and 8-K announcements
- SEC companyfacts for revenue and diluted EPS
  (the request uses a non-routable `research@example.com` contact because
  EDGAR requires that header shape; it is not an account or a credential)
- Alpaca raw daily closes and timestamped trades, rounded half-up to cents; SIP is tried
  first and IEX is used when a complete SIP download is unavailable; later
  downloads use the book's selected feed and do not switch silently
- short excerpts from available SEC primary filings and Alpaca split records
- Yahoo `^SP500TR` as the preferred S&P 500 total-return level
- Yahoo headline RSS when the feed parses

A new single-Sol book opens only when its opening evidence contains an eligible
Alpaca close and all price evidence uses that same feed. If it is missing or
mixed, collect again before opening; no ledger or review is created. An existing
single-Sol book without a valid opening feed is refused by the daily workflow:
retain its history and investigate rather than replacing its opening evidence.

Not collected, and not filled in:

- X, because no authorized X API credential is configured
- company investor-relations pages; SEC filings are the official-announcement record
- a price-only SPY level is used only if `^SP500TR` is unavailable, and it is
  labeled `price_only_substitute`, not total return

IEX covers a subset of market activity. Raw bars do not credit dividends.
Date-only companyfacts are held until the end of the New York filing date;
that bound is not a measured acceptance time. The collection report records
gaps and fetch times. The pilot's default state is
`~/.local/share/drift/prospective-single-sol`; state inside the checkout is refused.

## Calendar

Before opening new observation books, `configure-window` captures the published
NYSE holiday and early-close table and selects the next 20 future sessions plus
five settlement sessions. It retains the response and actual receipt time in the
state directory. The mode and book bind to that immutable window; a different window requires
a separate state directory. Existing v0.2 books retain their original calendar.

The review window starts at the exchange open and ends at 23:59 UTC. A daily
run rechecks the remaining dates and hours against the current NYSE publication
before collecting data. A changed, unavailable, or incomplete calendar stops
the run. Price rows outside the published calendar's covered years are withheld,
which can leave historical research incomplete. A published schedule can still
change without advance notice. If the first session passes before the book
opens, use a new state directory for a fresh window rather than backdating a
decision.

No observation decision is recorded before that window. A readiness drill
uses a separate ledger and does not count. Its simulation checks split coverage
and timestamped execution data, but does not exercise observation seals.

## Commands

```bash
uv run python -m drift.prospective configure-window
uv run python -m drift.prospective collect
uv run python -m drift.prospective daily --role observation
uv run python -m drift.prospective submit --role observation --proposal sol=/path/to/sol.json
uv run python -m drift.prospective resolve-expired --model sol --proposal-id <proposal-id> --reason "unanswered after cutoff"
uv run python -m drift.prospective daily --role readiness
uv run python -m drift.prospective status --role observation
```

`daily` does not call a model. The first run records the review context in its
book and writes `sol/prompt.txt` and a receipt. Submission
uses `submit`, without fetching new market data. It checks the saved context,
binds an intent, uses the local wall clock for the
decision, and writes a seal only after the decision commits. Fills require a
matching seal and later observations. Once an intent is recorded, only the
identical proposal can be retried for that review; altered proposals are refused.
Some early refusals, such as a submission clock behind a ledger event, leave an
intent without a decision. Once the underlying condition is resolved, the same
proposal can be retried within the review session. An interrupted seal can also
be recovered by resubmitting the identical proposal. Unanswered receipts are
retained rather than silently replaced, including late receipts requiring manual
resolution.
An expired unanswered or interrupted review can be explicitly resolved without
inventing a decision or making an unsealed decision executable. The ledger also
refuses a new decision on a settlement-only date. A
closing price is recorded only when the query covered the close and that
symbol's own response arrived after it. The benchmark time is its receipt time.
A bar with no fetch time cannot claim that close. Optional user notes
are `--suggestions notes.json`, a list of `symbol`, `summary`, and
`observed_at`. A suggestion is recorded as such and cannot by itself
support a trade.
Suggestions outside the authorized universe are kept separately and returned as
escalations; they do not expand trading authority. An incomplete corporate-action
response suspends the pilot. An unadjusted split blocks affected valuations and
fills, and research returns do not span that split. Corporate-action coverage
uses its own response receipt time, not the later batch completion time.
If a filled print is later invalidated, further fills and valuation are withheld;
there is no automatic accounting correction. Trade updates are checked when a
symbol is queried; there is no continuous correction feed. A notice is retained
even during a corporate-action outage. A notice affecting a filled trade
blocks further execution and valuation until resolved.
Unknown model cost stays unknown. Do not record a billed amount as zero
unless the runtime returns one.

### Direct Responses path (live billing gate closed)

The supervised direct request reads the pending review from the verified ledger,
puts its context inline, sends no tools, and uses the public Responses endpoint.
Its model and effort request are checked against the completed response. The
submission intent records the route, response ID, requested and observed model
and effort, account-subject hash, issued client ID, and review hash. These are
runtime records, not cryptographic proof of provider behavior. The historical
`codex/...` proposal identity remains a compatibility label, not evidence that
the direct request used Codex. Existing ledger, risk and seal checks remain in
force.

**Live inference is disabled:** the billing gate always refuses because no
account-specific no-extra-billing verifier has been implemented. The plan may
also use available credits, so sign-in alone is insufficient. The direct request
and submission path is tested with mocked HTTP, not a live account. Model
availability, xhigh behavior, account matching, and costs remain unverified.
Independent review and the operational prerequisites are required before use.
Sign-in validates the ID-token signature and identity before saving. The request
path also checks the retained ID token against current OpenAI signing keys and
the selected subject before inference; an expired ID token requires sign-in
again even if an access token remains usable.

The separate Drift sign-in component in `tools/chatgpt-signin` extracts the
Apache-2.0 TradingAgents sign-in, private-file and lock code at revision
`121265d18d467ac717f7af99cb0d669c15d2e73c`. Its LICENSE and NOTICE accompany
the code; changes are marked in source. The component uses a Drift-specific
registration and private credential file, not TradingAgents credentials. The
restricted OpenAI DevKit was not copied. The OpenAI Python SDK is Apache-2.0;
HTTPX is BSD-3-Clause, PyJWT is MIT, and cryptography is Apache-2.0 or
BSD-3-Clause. The component has been tested using synthetic OAuth and
local callbacks, not a real registration. See the [OpenAI flow documentation](https://developers.openai.com/siwc/token-sharing-open-source).

After review, from a source checkout build the sign-in component with `npm ci --ignore-scripts` and
`npm run build` in `tools/chatgpt-signin`. `node dist/cli.js signin` prints an
authorization address; open it in a browser on the same computer and authorize
Drift. `node dist/cli.js status` displays the saved account and subject without
tokens; `node dist/cli.js refresh` refreshes without displaying credentials.
The component stores its own protected credentials under
`~/.local/share/drift/chatgpt-signin/`. Never paste a callback URL or token into
chat. The supervised request command is `python -m drift.prospective.direct_responses
--state <state-dir> --expected-subject <subject>`; it remains blocked by the
billing gate even after sign-in.

Significant-event review is the same daily command. New 8-K accessions are
listed on the collection. There is no intraday scheduler in this revision.
Run the command after the session open, and again on the next session so
the prior decision can fill.
