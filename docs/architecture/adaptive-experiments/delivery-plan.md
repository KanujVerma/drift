# Delivery plan and independent work

This is durable sequencing and acceptance policy, not a mirror of GitHub state.
Task keys below are stable scope identifiers. Actual issues, writers, blockers
and PRs are discovered in GitHub through those keys.

## Ownership and precedence

Use [workstreams](../workstreams.md) and
[ADR 0017](../../adr/0017-transfer-scientific-experiment-ownership-to-kanuj.md).
Kanuj owns transferred scientific work only after the specific issue's required
migration receipt, metadata reconciliation and writer handoff. This document
does not activate an unmigrated issue or release another writer. Historical
Harsha references do not override current routing for an already migrated issue.
Independent scientific acceptance cannot be supplied by the author of the
methodology or measurement under review.

## Phase 0: adopt policy without disrupting work

SETUP prepares the docs and the blocked queue. The common routing activation
is separate from each person's access activation, so one unresolved login does
not freeze the other workstreams. HANDOFF records writer reservations and target
ownership. Existing research and historical pull requests are reviewed
separately. Setup does not merge, rewrite or certify them.

## Phase 1: parallel contract and methodology work

- Krish: the research-context contract. Produce CONTEXT/CANDIDATE, eligible
  learning, comparator implementation, model replay and original attempt/cost
  receipts. Consume the separately accepted experiment and eligibility contracts.
- Kanuj, scientific workstream: the experiment contract, methodology, metrics,
  study plan, trial completeness and cost attribution, after the issue-specific
  transfer gates. Preserve independently checked definitions and review.
- Matthew: source and result contracts, source rights and calendars, the minimal
  triage envelope, authoritative accounting, acquisition, execution timing,
  mandatory risk, recovery and containment mechanisms.
- Kanuj, separate triage slice: bounded offline behavior and its runtime only
  after the minimal source envelope and behavior contract are accepted. This
  separate slice does not limit his migrated scientific responsibilities.

Design and fixture work does not wait for another person's finished runtime.
Production consumers wait for the specific accepted interface. Synthetic fixtures
are not authentic coverage, proof of profit, validated fills or permission to
call a provider.

## Phase 2: smallest feature implementations

After each accepted contract, create exact producer-owned runtime child issues
with signatures, permitted paths, RED/GREEN cases, compatible versions and
stop conditions. Do not mark a broad parent READY as blanket implementation
permission. The setup agent creates no runtime classes or code stubs.

Krish's first slice emits bounded AI and R proposals from fixed context, with
replay and spending records. Matthew's first slice accepts a scripted proposal
against fixture inputs and yields a risk rejection or an accepted, partial or
unfilled result with reconciled cash and positions. Kanuj's scientific slice uses
hand-calculated results and fake producer adapters to show isolated accounts,
all-trial records, cost attribution, missing-evidence refusal and a report.
Kanuj's accepted triage later replaces fixture alerts. None of these slices is
permission to trade.

## Phase 3: end-to-end evidence

INTEGRATE freezes the first cross-owner acceptance test. Start with a small
synthetic example, then the accepted historical foundation, then a bounded
real-news/intraday example with authorized data. Finish the existing daily
benchmark independently; do not expand an active PR into every new feature.

Real intraday integration requires the versioned timing contract, data and
rights, latency/fill assumptions, accepted accounting and reviewed metrics.
Real multi-ETF work requires authentic venue/calendar support; do not guess
exchange identities or remove evidence floors. Fixture readiness is not evidence
that any of those dependencies are done.

## Phase 4: preregistered campaigns and forward readiness

Run only the accepted primary/secondary experiment matrix, preserving all
attempts and holdout integrity. FORWARD defines prospective operating readiness.
Actual provider/broker-connected operations require a separate explicit approval.
No stage of this delivery plan grants real-money authority.

For Stage 1, distinguish synthetic G2 integration from source qualification,
the admitted G3 study freeze, historical G4 evidence and prospective G5 evidence.
A development-only calibration plan precedes fitted artifacts; complete original
inputs and acceptance receipts precede the final freeze. Preserve the one
authoritative evaluator and account ledger. A locked design, mock artifact or
implemented runner cannot supply missing source rights, empirical calibration,
independent acceptance or elapsed prospective sessions. Optional news, intraday
and later model variants remain separate experiments rather than silent changes
to the primary selector study.

## Integration and workload rules

Kanuj owns the integrated scientific acceptance design for migrated issues,
without independently accepting his own methods or measurements. Matthew owns
platform producer changes. Krish owns producer fixes inside the learning loop.
Kanuj is not a required final reviewer of every PR or an infrastructure rescuer.
Do not invent equal effort shares. Existing single-writer claims and exact
producer/consumer acceptance requirements remain in force.

For unresolved design parameters, the owner writes an evidence-backed proposal
in its specification issue. The implementation agent does not select missing
production defaults. Small local code details within accepted contracts do not
require a new architecture discussion.
